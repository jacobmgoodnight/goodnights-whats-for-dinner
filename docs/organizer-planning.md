With no active vote it restores **So... what's for dinner?** and the original start/manage links. Other open votes remain accessible. - Review uses compact editable meal/cuisine, places, people and method rows. Optional settings remain under **Voting options**. Automatic ties default **off**. An explicit **Automatically decide a positive tie** opt-in is disclosed in invitations and ballots. At completion, the database saves the existing random-draw RPC's one immutable choice among positive tied leaders, even with the organizer's phone closed. All-no and zero-ballot results remain unresolved. Saved historical outcomes and all ballot/tally rules remain intact. Manual ties and runoffs remain available.
- A named preset saves only editable place/member IDs, meal, method, explicit cuisine, title and voting options. **Use** reopens Review after fetching current membership/restaurants. Unavailable choices are omitted, named and explained; insufficient choices block creation. Saving/updating/removing a preset creates no poll. Confirmation revalidates again and creates fresh credentials/ID, never copying ballots or results. Maximum 20 active presets/family with normalized unique names. Repeat-dinner drafts retain the title but require a fresh automatic-tie opt-in.
- Active personal members can suggest a restaurant, location, cuisine and short note from their home screen. The organizer reviews through H4's location/duplicate/hidden-entry workflow. Saving a current family location must succeed before acceptance. Review retries are idempotent; conflicting repeat decisions reject. Suggestions never silently change an active poll. Limits: 10 pending/member and 100/family; duplicate pending name/address submissions return the original suggestion. Group credentials cannot nominate.
- Titles are optional, max 80 characters, public with the poll, and appear on ballots, invitations, reminders, history, results and images. Blank titles retain normal meal/cuisine presentation. The optional family caption is max 100 characters, organizer-editable and saved separately as a default. Image inclusion starts unchecked on each opened poll. Names/photos remain separately opt-in. Caption edits invalidate an old prepared image; outcome wording/draw disclosure remain authoritative.
- Successful creation hands off to invitation preparation before refreshing Home data. Messages remain user-sent. No automatic texting, paid provider, palette change, framework, H5 meal record or rotation rule is included. Native Top 3 menus still show names only, with details below.

## Organizer alerts

Home lists the latest ten server-recorded completion/resolution events: decided, tie, all-no and empty closure. There is no historical backfill. Optional Web Push requires the organizer's explicit **Enable alerts on this device** tap, a supported HTTPS browser and permission. On iPhone/iPad it requires the installed Home Screen app. Installation alone never subscribes or requests permission. See [WebKit's requirements](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

The service worker handles push/click only: no fetch interception, cache or offline ballot queue. Generic messages contain a known event kind, event ID and public poll ID; they omit family names, titles, restaurants, contacts and invitation credentials. Clicks open only the app's public poll URL, using credentials already stored in that browser. They focus a matching poll and avoid replacing another open ballot. Device permission and Focus settings still apply.

The database queues one delivery/event/device. The private worker leases at most 12 at a time with three parallel sends, Web Push encryption and VAPID signatures. Only Apple, FCM and Mozilla HTTPS push endpoints are allowed; redirects are prohibited and requests have timeouts. Events expire after 24 hours; deliveries have at most three attempts with expiring two-minute leases. HTTP 404/410 disables an expired subscription. The scheduler makes a bounded direct HTTP request once/minute. Ballot triggers never send a network request; a dispatcher error preserves the successful ballot and durable queue. Private authorization headers never enter pg_net’s platform-readable request table. Delivery can begin up to a minute after completion. Delivery is at least once, not guaranteed device receipt; event tags replace duplicate notifications. Disable revokes server delivery before local unsubscribe; an in-flight send may still arrive.

Private VAPID/scheduler keys belong only in Vault. Browsers cannot read these, subscriptions, the queue or worker configuration. Worker RPCs are service-role-only; organizer/member RPCs follow existing token guards and RLS. The Edge Function disables gateway JWT verification because its handler requires a private 64-hex scheduler bearer key before claiming/sending. Its service-role key comes only from the hosted runtime. The pinned server-only dependency is web-push 3.6.7 with a Deno 2.1-compatible version-4 lock. The no-build frontend gains no package dependency.
